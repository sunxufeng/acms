## 一、先说三条调研结论（有两条和预想不同）

### ① 「可见范围默认部门内可见」——**现在已经是这样了**

`MEETING_VISIBILITY_SCOPES[0]` 就是「部门内可见」，表单用 `defaultFirstOption` 取第一项。
新建时默认值已经正确，不用改。真正要改的是下面 ②。

### ② 你说「可见部门就是部门里填写的部门」——这里藏着一个**会静默失效的坑**

现状两条路径**口径不同**：

| 可见范围 | 判据用的字段 | 值的形态 |
|---|---|---|
| 部门内可见 | 记录的「部门」字段 | **部门名**（如 `"学术轨"`） |
| 指定部门可见 | 「可见部门」字段 | **部门 id 数组**（`["od-8a06…"]`） |

后端 SQL 侧的条件是 `data->>'部门' = '学术轨'`（**等值匹配**）。

**一旦「部门」改成多选**，该字段的值变成数组 `["od-1","od-2"]`，
`data->>'部门'` 返回的是这段 **JSON 文本** ⇒ 等值匹配**永远不命中**。

后果：这条纪要**对同事全部隐身**（创建者自己靠另一条分支还能看到），
**列表不报错、详情不报错**，只有「别人说看不到」时才可能发现 —— 是本次改动最大的风险点。

⇒ 所以「部门」改多选**必须连判据一起改**，这是同一个改动，不能拆。

### ③ 「UI 难看」的真正原因——不是样式，是 **84 个复选框全铺开**

线上实测（新建表单）：参会人员 28 个 + 缺席人员 28 个 + 列席人员 28 个 = **84 个复选框**
直接铺在表单里，占 3 屏以上；「可见用户」再来 28 个。候选人只能一个个点。

对照你指定的参考对象「学生记录」表单：17 个字段、**0 个复选框**、有分区标题。

## 三、两个新控件

### 1. `departmentTree` 部门多选树

- 树形展示（公司 → 一级部门 → 二级部门），带复选框
- **级联**：勾父级 → 子树自动全勾；取消某个下级 → 父级显示**半选态**
- 已选区在下方以 chip 展示，可逐个删
- **存部门 id（`od-…`）而不是名字** —— 这是关键：
  - 免疫重名（部门名互为子串时会串台，现在的 9 个部门名恰好互不为子串，但加一个「教学中心」就可能撞上「教学管理中心」）
  - 免疫改名（改名后历史记录依然有效）
  - 与「可见部门」字段**同一种值形态** ⇒ 判据可以合并成一套

### 2. `peoplePicker` 人员多选

- **已选**：一行 chips，可删
- **候选**：收进**可搜索下拉**（输入姓名即筛），不再全铺
- 「参会人员」附加 **「按部门带出」**：一键加入所选部门（含下级）的成员，可再逐个取消

> 这一套控件同时用于 参会人员 / 缺席人员 / 列席人员 / 可见用户 四处
> → 从 **112 个复选框** 变成 **4 个输入框**。

## 四、自动联动规则（你明确要求的两条）

| 触发 | 行为 |
|---|---|
| 选了部门 | ① 该部门（**含下级**）成员自动加入**参会人员** |
| | ② 可见范围自动置为「**部门内可见**」 |
| | ③ 可见部门自动 = 所选部门（id 同值） |
| 手动删掉某人 | 再改部门时**不会把他加回来**（用「已手动移除」集合记着） |
| 手动改过可见范围 | 只在该字段**为空**时自动填；用户已选过就不覆盖（避免抢用户的操作） |

关于「含不含下级」我按**含下级**设计（学术轨直系 1 人，含子树 11 人；
选「学术轨」的会议本来就该叫上三个中心的人）。这条影响体感最大，见第六节待确认。

## 五、判据改造（本次的核心技术动作）

把两个分支**合并成同一种口径**：

```
部门内可见  →  可见部门 contains 我的部门 id 集合
指定部门可见 →  可见部门 contains 我的部门 id 集合   （取值来源不同，判据同一段代码）
```

- 「部门内可见」时：可见部门由**「部门」字段自动派生**（用户不用重选）—— 正好就是你要的「可见部门就是部门里填写的部门」
- 「指定部门可见」时：用户手选可见部门（现状不变）
- 值形态统一为 id ⇒ `contains` 子串匹配安全（id 互不为子串）
- 顺带收益：判据少一支分支，两处不再可能漂移

**历史数据回填**（会议纪要现存量极少，实测只有 2 条）：

| 记录 | 现状 | 处理 |
|---|---|---|
| `rec_1b799e4f…` | 部门=「学术轨」（名字）· 可见范围=指定部门可见 · 可见部门=2 个 id | 「部门」补成 id 数组；可见范围/可见部门不动 |
| `rec_2e061e53…` | 部门=「Arete AI Lab」· 可见范围=指定用户可见 · 可见部门=[] | 只补「部门」为 id 数组；可见范围是「指定用户可见」，判据不碰可见部门 |

回填脚本幂等、只填空、带备份（沿用 `scripts/backfill_*.mjs` 的既有写法）。

## 七、验证计划

1. **权限视角实测**（最关键）：用**身份模拟**切到别人身份，验证
   - 同事 A（在所选部门内）能看到这条部门内可见的纪要
   - 同事 B（不在部门内）看不到
   - 选多个部门时，任一部门命中即可见
2. 级联正确性：勾父级 → 子级全勾；取消 1 个 → 父级半选；再勾回 → 父级恢复全选
3. 联动正确性：选部门 → 参会人员自动带出、可见范围/可见部门自动填；手动删掉的人不被加回
4. UI：表单从 84 个复选框降到 0；分区标题正确；窄屏不溢出
5. 回归：邮件账户页的「关联用户」多选仍正常
6. 历史 2 条记录：回填后各自能被正确的人看到
