它挂在「IDP 方案」下面（idpCommunication，字段：关联IDP方案 / 沟通日期 / 沟通人 / 沟通内容 / 需要的帮助·下一步计划 / 原始文档）， 入口在「IDP管理」页 /idp-plans 里，沟通记录必须先建一个 IDP 方案才能挂上去。

好消息：它和「IDP方案」表目前都是 0 行 —— 建了但从来没被用过；「学生记录」现有 2 条数据，都是「日常跟进」。

所以这次的需求会带来一个岔路：系统里会出现"两处都能记 IDP 沟通"。现在没数据、风险很小；只要两边都开始用， 就会出现「同一件事一半记在这、一半记在那」，而学生全景 / 搜索 / AI / 导出各读一处 ⇒ 谁也看不到全貌。 请先在这三个里选一个（见「一、要你选的第一件事」）。

一、要你选的第一件事：那张已有的 IDP 沟通表怎么办

A · 推荐：学生记录里加类型，把 /idp-plans 的「IDP沟通」收起来

「IDP沟通」统一在学生记录里记；/idp-plans 只保留「IDP 方案」本身。

  • ✅ 一处入口，不用先建方案再挂沟通
  • ✅ 学生全景、搜索、AI 汇总、导出天然都能看到（它们都读学生记录）
  • ✅ 权限沿用「日常跟进」，不用改任何角色配置
  • ⚠️ 那张表现有 0 行 ⇒ 收起它不会丢任何数据

B / C · 备选

B 两边都留着用：需要你把分工定死（比如"正式 IDP 会议走 A、日常随口聊走 B"）， 否则必然出现重复与遗漏。我不建议。

C 不加类型，改成把那张表的沟通聚合进学生记录（只能看不能改）：与你要的 「新建、修改」不符，且必须先在 IDP管理 里建方案才记得了。

二、现状：这套「记录类型」是怎么实现的

一句话：一张表 + 一个「记录类型」单选字段。日常跟进 / 家校沟通 / 学生观察 三类记录共用同一张物理表 （沿用原来「日常跟进表」），靠类型字段区分。三条链路各自读同一份类型定义：

链路实现位置作用
类型 → 权限 packages/contracts/src/student-records.ts
（类型 → moduleKey 映射）		 后端按「你持有哪个类型的模块权限」逐类型过滤读与写：看不到没权限的类型，也建不出没权限的类型
类型 → 表头措辞 apps/web/app/student-records/columns.tsx 的 WORDS 日常跟进/家校沟通用「沟通人 · 沟通主题 · 沟通时间」，学生观察用「观察人 · 主题 · 观察时间」
类型 → 字段显隐 同上，showIf 里硬编码 只有家校沟通显示「家长 / 家长反馈态度 / 家长反馈」；只有学生观察显示「观察类型」
类型 → 顶部 Tab student-records/page.tsx Tab 由类型定义自动生成，新类型会自己出现，不用改 Tab 代码

✅ 一个让改动量变小的发现：类型定义里的 ownFields（该类型专属字段）与 legacyPath（旧页面地址） 目前没有任何代码在消费 —— 它们只是声明。字段显隐实际由前端 showIf 决定。

而「IDP沟通与日常跟进完全相同」恰好等于什么都不用加：日常跟进本来就是「全套公共字段 + 没有任何专属字段」。 所以这次不需要碰显隐逻辑。（如果以后要给 IDP沟通 加专属字段，就要同时改 showIf，我会在代码注释里写明。）

四、要你拍板的第二件事：IDP沟通 归谁管（权限）

每个类型要挂一个模块权限点，它决定「谁能看、谁能建」。这里只有两个选法，后果差别很大：

选项效果代价 / 额外要做的事
A · 推荐：复用「日常跟进」的权限 任何能看到/能写日常跟进的人，同时就能看/能写 IDP沟通。
上线即生效，一个角色配置都不用改		 不能单独授权（"只想给 IDP 导师看 IDP沟通、不给看日常跟进"做不到）。
将来真需要分开，再单独加权限点也不晚
B · 用「IDP管理」的权限 语义更贴切（IDP 的事归 IDP 模块 🔴 新权限点默认没人持有 ⇒ 上线后除管理员外所有人都看不到 IDP沟通， 你得逐个角色去「权限矩阵」里勾。
还要额外做三件事：加权限行、把权限行挂到菜单下（不挂的话矩阵里没有这一行可勾）、跑一次权限版本迁移

我的建议是 A。理由：既然内容和敏感度都与日常跟进完全相同，就没必要为了"看起来更整齐"多造一个权限点， 换来的却是「上线了但没人能看见」这种最容易误判为 bug 的状态。（这个坑我们前几天刚在别的模块上踩过： 新权限点没人勾 ⇒ 功能等于不可用。）
